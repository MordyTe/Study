# אפיון מוצר: מערכת תמלול אולפן בדיוק גבוה (עברית + אנגלית)

## 1. הקשר (Context)

באולפן השידור יש 3 מחשבים חזקים שמריצים OBS + vMix (שידורים חיים + הקלטת פודקאסטים),
במה עם מיקרופונים קוויים ואלחוטיים, מיקסר דיגיטלי **Behringer X32**, וכל האודיו/וידאו
מחולק על גבי **Dante** (אודיו-over-IP) ו‑**NDI**. המיקרופונים נשמעים גם בקונטרול וגם
ברמקולי האולם.

**הצורך:** כלי שמתמלל את מה שנאמר באולפן בדיוק גבוה מאוד, מתעד בכתב מה נאמר, ונותן גם
כתוביות בזמן אמת. הדיוק הוא הדרישה מספר אחת.

**הכרעות שהתקבלו מול המשתמש:**
- **שפות:** עברית + אנגלית בלבד (כולל ערבוב תוך-משפטי / code-switching — תרחיש מרכזי).
- **פרטיות/עלות:** ענן מותר, אך התוכן רגיש ולכן מקומי עדיף כברירת מחדל.
- **מטרת הפלט:** גם זמן אמת (כתוביות) וגם תמלול מדויק סופי לתיעוד — ארכיטקטורת שתי שכבות.
- **חומרה/GPU:** יש NVIDIA GPU, אך בזמן הקלטות/שידור המחשב עמוס מאוד; צריך להתחשב בעומס,
  ואם יהיה כבד מדי — להעביר לענן.

**תוצאה מבוקשת:** מוצר שמתמלל ברמת דיוק ~5% WER בעברית נקייה, מזהה דובר לפי מיקרופון,
מתעד הכל לארכיון ניתן לחיפוש, ומוציא כתוביות חיות לשידור — בלי להכביד על מחשבי השידור.

---

## 2. סקירת המוצר (מה הוא עושה)

מערכת שמקבלת את **כל ערוצי המיקרופון בנפרד** מה‑X32 (דרך Dante), ומריצה צינור תמלול
דו-שכבתי:

- **שכבה חיה (Live):** כתוביות בזמן כמעט-אמת (~0.3–1.5 שנ') שמוזרמות ל‑OBS/vMix לשידור.
- **שכבה מדויקת (Archive):** תמלול סופי מדויק לכל ערוץ, מתוקן ומפוסק, נשמר לארכיון
  ניתן לחיפוש וייצוא (SRT/VTT/TXT/DOCX).

כל ערוץ = מיקרופון אחד = דובר אחד → **תמלול מתויג-דובר ללא diarization**.

## 3. משתמשים ותרחישי שימוש

| משתמש | תרחיש |
|---|---|
| טכנאי קונטרול | מפעיל/עוצר תמלול, מנטר איכות, מתקן תיוג דוברים, מפעיל כתוביות לשידור |
| עורך תוכן / מפיק | מחפש בארכיון ("מה נאמר על X"), מייצא תמלול פודקאסט ל‑DOCX, מפיק כתוביות |

תרחישי-על: (א) הקלטת פודקאסט 2–4 אנשים → תמלול מדויק מתויג-דובר לעריכה/פרסום.
(ב) שידור חי → כתוביות בזמן אמת. (ג) תחקור/ארכיב → חיפוש טקסטואלי בכל מה שנאמר אי-פעם.

## 4. דרישות פונקציונליות

1. לכידת עד 32 ערוצי מיקרופון נפרדים בו-זמנית מה‑X32.
2. תמלול עברית + אנגלית, כולל ערבוב תוך-משפטי.
3. תיוג דובר אוטומטי לפי מספר ערוץ (מיפוי ניתן-לעריכה: ערוץ 1 → "מנחה" וכו').
4. חותמות זמן ברמת-מילה, מסונכרנות בין כל הערוצים.
5. כתוביות חיות ל‑OBS (דרך obs-websocket) ול‑vMix (דרך vMix API / Data Source).
6. אחסון מתמשך ניתן לחיפוש (לפי טקסט/דובר/תאריך/תוכנית).
7. ייצוא: SRT, VTT, TXT, DOCX (תמלול מתויג-דובר).
8. **מילון מותאם (glossary)**: שמות מנחים/אורחים/תוכניות + מונחי אנגלית (מותגים/טכנולוגיה)
   — להטיית המנוע ולתיקון post.
9. מסך ניטור חי: טקסט מתגלגל לפי ערוץ + אינדיקציית ביטחון (confidence).
10. מצב offline (רק מקומי) + מצב hybrid (ענן בעומס/לקוד-סוויצ'ינג) — מתג.

## 6. ארכיטקטורה מומלצת

### 6.1 טופולוגיה — פתרון בעיית העומס

**המלצה מרכזית: node תמלול ייעודי.** מכיוון שהאודיו על Dante, מחשב נפרד נרשם לאותם
ערוצי מיקרופון דרך **Dante Virtual Soundcard (DVS)** — בלי לגעת במשאבי OBS/vMix.

```
            X32  ──(X-DANTE card, clock master, 48kHz)──┐
                                                         │  רשת Dante (VLAN ייעודי)
 מחשבי שידור (OBS/vMix) ──────────────────────────────┤
                                                         │
            >>> node תמלול ייעודי (DVS → ASIO 32ch) <<< ─┘   ← הכלי רץ כאן
```

- **העדפה:** מחשב רביעי צנוע עם GPU, או המחשב הכי פחות עמוס מבין השלושה.
- **אם חייבים על אותו מחשב של השידור:** להגביל את ה-GPU/CPU של התמלול, ולהעביר את
  השכבה המדויקת לענן בזמן הקלטה כבדה (מתג hybrid).

### 6.2 לכידת אודיו מה‑X32 (יסוד הדיוק)

- **כרטיס:** **X-DANTE** (32×32 Dante, מומלץ — משמש clock master) או **X-USB** הקיים
  (32×32 USB, חינם). שניהם נותנים 32 ערוצים ב‑stream אחד של **ASIO**.
- **ניתוב:** Direct-Out של כל ערוץ ← ערוץ כרטיס תואם (ניתוב בבלוקים של 8 ב‑X32).
- **נקודת ההקשה (tap):** **pre-fader, אחרי ה‑gate (PreEQ)** — ה‑gate חוסם דליפה/הדהוד
  מרמקולי האולם, וה-pre-fader מבטיח שתנועות fader ומיקס הניטור לא משפיעים על פיד התמלול.
  לכוון gate שמרני (range −20dB, release איטי) כדי לא לקטוע מילים חלשות.
- **קוד לכידה:** stream יחיד של ASIO ב‑48kHz → פירוק ל‑N buffers → downsample ל‑**16kHz
  mono** לכל ערוץ. ספריות: **python-sounddevice** (PortAudio+ASIO) או **NAudio** (.NET).
- **NDI לא לאודיו** — ה-virtual input של NDI מגיש stereo יחיד; נשאיר NDI לווידאו.

### 6.3 צינור העיבוד (Pipeline)

```
32ch ASIO (16kHz mono/ערוץ)
   → ring buffer לכל ערוץ
   → Silero VAD לכל ערוץ (רק דיבור אמיתי עובר — אנטי-הזיה #1)
   → ┌ שכבה חיה:   מנוע streaming → כתוביות (partial+final) → OBS/vMix
     └ שכבה מדויקת: ivrit.ai large-v3-turbo + יישור + תיקון-LLM מבוקר
   → מיזוג ציר-זמן בין ערוצים (clock משותף → סנכרון מדויק)
   → תצוגה חיה + אחסון (SQLite/JSONL עם חותמות-מילה)
   → ייצוא SRT/VTT/TXT/DOCX
```

### 6.4 מנועי ASR מומלצים

| שכבה | מנוע מומלץ | מיקום | הערות |
|---|---|---|---|
| **Archive (מדויק)** | **ivrit.ai whisper-large-v3-turbo (CT2)** ב‑faster-whisper | מקומי | ~5% WER, Apache-2.0, פרטי. `language=he`, Silero VAD on, `condition_on_previous_text=False`, initial_prompt=glossary |
| **Live (מקומי)** | **ivrit.ai zipformer2-66m-streaming-he** (sherpa-onnx) | מקומי | real-time אפילו על CPU; חלש באנגלית/מספרים → תיקון בשכבת archive |
| **Live (code-switching גבוה)** | **Soniox v5** (או ElevenLabs Scribe v2 Realtime) | ענן | הכי טוב לערבוב עברית-אנגלית חי; מתג אופציונלי כשיש הרבה אנגלית |
| **Fallback בעומס** | Soniox / ElevenLabs / Azure he-IL | ענן | כש-GPU עמוס מדי |

> הכרעה חשובה: Whisper-רגיל **לא** מתאים לעברית — תמיד ה-fine-tune של ivrit.ai.
> ל‑code-switching חי, המודל המקומי חלש באנגלית; לכן או ענן (Soniox) בזמן אמת, או
> הסתמכות על שכבת ה-archive המדויקת + תיקון-LLM לשחזור אנגלית.

### 6.5 כתוביות חיות לשידור

- **OBS:** מקור Text (GDI+) שמתעדכן דרך **obs-websocket** (`SetInputSettings`); throttle ~2–4/שנ'.
  אופציונלי `SendStreamCaption` ל‑CEA-608 ל‑YouTube/Twitch.
- **vMix:** Title + **vMix API** `SetText`, או **Data Source** שקורא קובץ שהכלי מעדכן.
- לשידור SDI/608 תקני — enc כתוביות חיצוני.

### 6.6 אחסון, חיפוש וייצוא

- אחסון: SQLite + JSONL עם `{speaker, start, end, words[], confidence}`.
- חיפוש: full-text לפי טקסט/דובר/תאריך/תוכנית.
- ייצוא: SRT/VTT (כתוביות), TXT (קריאה), DOCX (תמלול מתויג-דובר ל‑python-docx).

## 7. אסטרטגיית דיוק (לב הבקשה)

לפי סדר ההשפעה:

1. **ערוץ-לכל-מיקרופון** — מבטל diarization ומוריד דליפה/חפיפת-דוברים. המנוף הגדול ביותר.
2. **פיד נקי מה‑X32** — tap אחרי gate, pre-fader; gate חוסם דליפה והדהוד אולם.
3. **מודל נכון** — ivrit.ai fine-tune (לא Whisper רגיל). ~35–45% שיפור WER בעברית.
4. **Silero VAD** — אנטי-הזיה #1 (Whisper ממציא טקסט על שקט/מוזיקה).
5. **מילון/initial_prompt** — הטיה לשמות, מונחי אנגלית, איות עברי.
6. **הגדרות אנטי-לופ** — `condition_on_previous_text=False`, סינון `compression_ratio>2.4`,
   `no_speech_threshold=0.6`, `logprob_threshold=-1.0`.
7. **תיקון-LLM מבוקר** — מתקן פיסוק/מספרים/איות אנגלית, **מוגבל למקטעים בביטחון נמוך בלבד**
   (אחרת ממציא). ~10–20% שיפור WER יחסי.
8. **נרמול עברי** — הסרת ניקוד/bidi, גרש/גרשיים → `'`/`"`, נרמול מספרים לסטנדרט אחיד.

## 8. מחסנית טכנולוגית (Tech stack)

- **אודיו:** Dante Virtual Soundcard, ASIO; Python `sounddevice` (או .NET `NAudio`).
- **ASR מקומי:** `faster-whisper` + `ivrit-ai/whisper-large-v3-turbo-ct2`; `sherpa-onnx` +
  `ivrit-ai/zipformer2-66m-streaming-he`; `silero-vad`.
- **ASR ענן (אופ'):** Soniox / ElevenLabs / Azure Speech SDK.
- **תיקון-LLM:** Claude (דרך מנוי המשתמש) על מקטעי-ביטחון-נמוך.
- **אחסון:** SQLite + FTS; **ייצוא:** `python-docx`, srt/webvtt.
- **כתוביות:** `obs-websocket` client; vMix TCP/Web API.
- **UI:** אפליקציית דסקטופ/לוקאלית (Electron/web מקומי) לניטור ובקרה.
- **GPU:** 24GB (RTX 4090 / L4 / A10) נוח ל‑multi-channel; 12–16GB מספיק ל‑1–2 ערוצים.
  VAD-gating + batching → GPU בודד משרת את כל האולפן.

## 9. מדידת דיוק (Eval harness) — איך מבטיחים "מדויק"

הדיוק לא מובטח בהצהרה אלא במדידה על האודיו שלכם:

1. להקליט 2–3 תוכניות אמיתיות (פודקאסט + שידור עם code-switching).
2. לתמלל ידנית דגימות (~30–60 דק') כ‑ground truth.
3. למדוד WER עם **נרמול ivrit.ai** (ניקוד/bidi/גרשיים) — אחרת המספרים מנופחים.
4. A/B בין מנועים (ivrit.ai turbo מקומי מול Soniox/ElevenLabs ענן) **על האודיו שלכם**.
5. לכוון gate, VAD threshold, glossary, ותיקון-LLM — ולמדוד שוב.
6. לעקוב בנפרד אחרי over-correction (תיקון-LLM שממציא).

> ממומש היום ב‑`studio-transcribe eval ref.txt hyp.txt` — הנרמול תואם את ה‑leaderboard של
> ivrit.ai כך שהמספר בר-השוואה.

## 10. תוכנית בנייה בשלבים

- **שלב 0 — הוכחת יכולת אודיו:** לכידת 32ch ASIO מה‑X32 ל‑WAV נפרד/ערוץ; לאמת clock/סנכרון.
  *(ממומש: `capture/capture_asio.py`)*
- **שלב 1 — MVP תמלול מדויק (מקומי, offline):** ערוץ→VAD→ivrit.ai turbo→תמלול מתויג-דובר
  →ייצוא TXT/DOCX. למדוד WER (§9). *(ממומש: `studio_transcribe/pipeline.py` + CLI)*
- **שלב 2 — חיפוש וארכיון:** אחסון SQLite+FTS, UI חיפוש, ייצוא SRT/VTT.
- **שלב 3 — כתוביות חיות:** שכבת streaming → OBS/vMix; מתג ענן (Soniox) ל‑code-switching.
- **שלב 4 — hybrid + תיקון-LLM + מילון:** fallback ענן בעומס; תיקון-LLM מבוקר; ניהול glossary.
  *(תשתית תיקון-LLM ממומשת: `studio_transcribe/llm_correction.py`)*
- **שלב 5 — הקשחה:** ניטור, התאוששות מכשל, ביצועים, תיעוד תפעולי.

## 11. סיכונים והכרעות פתוחות

**לאימות באתר:** latency/CPU של DVS על 32ch; כיול gate מול קטיעת מילים; קצב עדכון כתוביות
מול ריצוד ב‑OBS/vMix; עומס דוברים בו-זמני אמיתי על ה‑GPU.

**הכרעות פתוחות למשתמש:**
1. **טופולוגיה:** node ייעודי לתמלול (מומלץ) מול ריצה על מחשב השידור? איזה מהשלושה / רביעי?
2. **כרטיס:** X-USB הקיים (חינם) מול רכישת X-DANTE (clock master, גמיש יותר)?
3. **כתוביות חיות:** מקומי (zipformer, חלש באנגלית) מול ענן Soniox (מצוין לערבוב, אך אודיו לענן)?
4. **מס' מיקרופונים/דוברים טיפוסי** בו-זמנית — לקביעת גודל GPU.
5. **שפת ה‑UI** (עברית?), ומתכונת הייצוא המדויקת לפודקאסטים.

## 12. אימות (Verification)

- **אודיו:** 32 קבצי WAV נפרדים מוקלטים מ‑32 ערוצי X32, מסונכרנים ל-sample (שלב 0).
- **דיוק:** WER נמדד על ground-truth שלכם ≤ יעד, עם נרמול ivrit.ai (שלב 1, §9).
- **זמן אמת:** כתובית מופיעה ב‑OBS/vMix תוך ≤1.5 שנ' מהדיבור (שלב 3).
- **תיוג דובר:** כל שורת תמלול נושאת את הדובר הנכון לפי ערוץ (שלבים 1–3).
- **עומס:** התמלול רץ בלי לפגוע ב‑OBS/vMix (הרצה על node ייעודי; שלב 1).
- **ייצוא:** DOCX/SRT/VTT תקינים נפתחים בכלים חיצוניים (שלב 2).
